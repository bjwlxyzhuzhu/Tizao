## 三、共用底座，不做两套系统

```
Tizao/
├── apps/web                     共用前端壳（登录、会话、步骤容器）
├── apps/server                  共用后端（账号、会话、审计、AI 网关）
├── packages/shared              共用类型、账号、会话契约
├── packages/sim-core            共用数值基础（统计、区间、归一化）
├── packages/scoring             共用赋分框架与能力画像
└── packages/experiments/
    ├── titan/                   B 项：工艺模型、24 步、3 个 3D 场景
    └── ai-safety/               A 项：安全模型、24 步、3 个 3D 场景
```

**共用的部分**：登录、会话、步骤状态机、赋分框架、能力画像、AI 网关、审计日志、部署。
**不共用的部分**：实验对象、知识点、24 步定义、评分规则、3D 场景、报告模板。

申报书里必须写明这一点：两个项目的**实验内容与教学目标完全不同**，只是共用技术底座。这是避免被判重复申报的关键表述。

## 四、项目 A 设计（朱丽叶负责）

### 4.1 基本信息

| 字段 | 内容 |
|---|---|
| 项目名称 | 人工智能实验安全风险识别与应急处置虚拟仿真实验 |
| 申报方向 | 实验室安全 — 人工智能实验安全 |
| 实验类型 | 综合设计型 |
| 对应专业 | 计算机类 0809；智能科学与技术 080907T；人工智能 080717T |
| 所属课程 | 《人工智能概论》实验 16 学时；《机器学习》；《智能体开发》 |
| 课时 | 4 学时（约 200 分钟） |
| 实验语言 | 中文 |

### 4.2 为什么必须虚拟仿真

| 必要性 | 具体场景 |
|---|---|
| 不可逆操作 | 真实数据一旦泄露无法收回；训练集投毒污染后无法回溯 |
| 高危环境 | GPU 服务器供配电与散热异常可致设备损毁 |
| 无法复现 | 提示注入、越狱、智能体越权需要隔离环境，真实系统上不可演示 |
| 高成本 | 大模型训练与推理成本高，学生无法反复试错 |
| 合规要求 | 个人信息、生成内容标识等操作必须在受控环境完成 |

### 4.3 法规依据（申报书直接引用）

- 《中华人民共和国网络安全法》
- 《中华人民共和国数据安全法》
- 《中华人民共和国个人信息保护法》
- 《生成式人工智能服务管理暂行办法》
- 《人工智能生成合成内容标识办法》
- 《信息安全技术 个人信息安全规范》GB/T 35273

**3D 场景（只做 3 个，控制工作量）**：
1. `lab_room` — 机房：门禁、配电柜、GPU 机柜、温度指示

其余步骤用表单、图表、对话完成。评审要求的是实质交互，不是每步都要 3D。

## 八、风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 一人同时推进两项，A 项被拖 | A 项做不完 | 学生在 B 项自主运转；朱丽叶每天只花 15 分钟管 B |

| 政审材料重复 | 退材料 | 两人分别出现在两个团队，各自出具政审意见 |
| 实验空间接口两套账号 | 联调来不及 | 10-21 就问清是否按项目开通 |
| 视频录两套 | 时间不够 | 先录 A 项，B 项用学生录屏 |
| 学校服务器两套部署 | 资源冲突 | 同一台服务器，不同端口与路径 |
