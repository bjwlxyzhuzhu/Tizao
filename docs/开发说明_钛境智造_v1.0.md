## 0. 一页纸摘要

**要做的东西**：一个浏览器直接打开、无需安装插件的虚拟仿真实验系统。学生登录后，用 24 步完成"钛合金构件从方案设计 → 熔炼 → 锻造 → 热处理 → 表面处理 → 人机协同工位评价 → 报告"的完整流程。每一步有参数输入、实时反馈、自动赋分。

**不做的东西**：影视级渲染、真实 CFD/FEA、多校区多租户、移动端原生 App。

**Day 7 验收标准（Definition of Done）**：
1. 一个网址能打开，登录进入
2. 24 步从第 1 步跑到第 24 步，不报错
3. 不同参数输入产生不同结果和不同分数
4. 自动生成实验报告
5. 3 个 AI 智能体可用，断网时有规则兜底
6. 3 个 3D 场景可交互
7. 能录出 5 分钟演示视频

**三条红线**：
- 学生个人服务器只能做开发/演示，**不得作为申报的生产入口**
- 不得把企业真实数据、学生个人信息提交到公共大模型 API
- 不得擅自更换技术栈、引入未经批准的新依赖

## 1. 项目边界

### 1.1 做什么

| 模块 | 内容 |
|---|---|
| 前端 | React 18 + TypeScript + Vite + Three.js(R3F) + Zustand |
| 3D | 3 个场景：VAR 熔炼、锻压成形、人机协同工位 |
| 仿真内核 | 降阶物理模型（热传导、偏析、相变、流变、再结晶、人机尺寸） |
| 交互 | 24 步，3D / 表单 / 图表 / AI 对话四种类型 |
| 评分 | 每步赋分 + 总分 + 能力画像 |
| AI | 3 个智能体：方案预评审、过程反馈、报告生成 |
| 后端 | Node 22 + Express + SQLite |
| 部署 | Docker Compose |

### 1.2 不做什么

- 不做真实熔池流体仿真（CFD）
- 不做有限元应力场（FEA）
- 不做产线级数字孪生
- 不做移动端适配（保证桌面浏览器可用即可）
- 不做多语言
- 不做支付、社交、消息推送

### 1.3 结果必须"因操作而异"

这是评审的硬要求。每一步的参数必须真实影响后续结果：
- 熔炼电流影响熔速、熔池深度、凝固组织
- 锻造温度影响流变应力和再结晶
- 冷却速率影响 α 片层厚度和硬度
- 人体百分位影响可达性和 RULA 评分

如果两个不同输入得到同一个结果，视为 Bug。

## 6. 仿真内核规格

### 6.1 通用约定

- 全部纯函数，放在 `packages/sim-core`，不依赖 React / DOM
- 单位：温度 °C，长度 mm，时间 s，应力 MPa，应变无量纲
- 每个模型一个文件，一个 `index.ts` 统一导出
- 参数集中在 `params.json`，每项必须标注 `source`
- `source` 取值：`standard`（国标/行标）、`literature`（公开文献）、`enterprise`（企业脱敏数据）、`assumed`（教学假设）
- **`assumed` 不得用于对外宣称的"真实数据"**

### 6.2 模型清单

#### M1 一维瞬态热传导

```
ρc ∂T/∂t = k ∂²T/∂x²
显式 FTCS：T[i]^(n+1) = T[i]^n + α·dt/dx² · (T[i+1] - 2T[i] + T[i-1])
稳定性：dt ≤ dx² / (2α)
```

输入：初始温度、边界温度、导热系数、密度、比热、网格数、总时间
输出：温度-时间序列、熔池深度、凝固时间

#### M2 凝固偏析（Scheil）

```
C_L = C0 · (1 - f_s)^(k - 1)
```

输入：初始成分、分配系数 k、固相分数序列
输出：液相成分、偏析指数

#### M3 二次枝晶臂间距

```
λ2 = A · LST^n
LST = 局部凝固时间 = (T_liquidus - T_solidus) / 冷却速率
```

输入：冷却速率、A、n
输出：λ2（μm）

#### M4 β→α 相变（Avrami）

```
X = 1 - exp(-k · t^n)
k = k0 · exp(-Q/(R·T_K))
```

输入：温度历程、k0、Q、n
输出：β 相分数随时间

#### M5 锻造流变应力（Zener-Hollomon）

```
Z = ε̇ · exp(Q/(R·T_K))
σ = (1/α) · asinh((Z/A)^(1/n))
```

输入：应变速率、温度、材料参数
输出：流变应力（MPa）

#### M6 再结晶（JMAK）

```
X = 1 - exp(-0.693 · (t/t50)^1.5)
t50 = A · d0^m · ε^n · exp(Q/(R·T_K))
```

输入：初始晶粒、应变、温度、时间
输出：再结晶分数、再结晶晶粒尺寸

#### M7 晶粒与硬度（Hall-Petch）

```
σy = σ0 + k · d^(-1/2)
HV ≈ σy / 3
```

输入：晶粒尺寸
输出：屈服强度、硬度

#### M8 人机尺寸（GB/T 10000）

```
dimension(P) = mean + z(P) · sd
z(P5) = -1.645, z(P50) = 0, z(P95) = 1.645
```

输入：百分位、性别、测量项
输出：尺寸值（mm）

#### M9 可达域

```
可达 = |shoulder - target| ≤ armLength
视域 = angle(target - eye, forward) ≤ FOV/2
```

输入：肩点、目标点、臂长、眼点、视锥
输出：布尔值、距离、角度

#### M10 RULA 简化

按上臂、前臂、腕、颈、躯干、腿六项查表，输出 1–7 分与动作等级。

输入：关节角度
输出：RULA 分值、动作等级、建议

#### M11 成本与成材率

```
成本 = 原料成本 + 能耗成本 + 工时成本 + 损耗
成材率 = 成品重量 / 投料重量
```

输入：各阶段参数
输出：成本明细、成材率

### 6.3 参数数据来源

- 国标/行标：GB/T 3620、GB/T 2965、ASTM B348、GB/T 10000
- 文献值：钛合金热物性、JMAK 参数
- 企业脱敏数据：由项目组提供，标注 `enterprise`，**不得提交到公共 API**
- 教学假设：用于简化，标注 `assumed`，在报告中标明

### 6.4 测试要求

每个模型至少 3 个单测：
1. 边界值（0、极大值）
2. 单调性（温度升高 → 应力下降）
3. 与文献/手算结果对比（误差 < 10%）

## 9. AI 层规格

### 9.1 三个智能体

| 智能体 | 触发 | 输入 | 输出 |
|---|---|---|---|
| 方案预评审 | S04 | 构件定义、牌号、人体尺寸 | 风险清单（JSON） |
| 过程反馈 | 异常步骤 | 当前参数、仿真结果、阈值 | 提示语（≤80 字） |
| 报告生成 | S24 | 全过程记录、评分 | Markdown 报告 |

### 9.2 提示词结构

```
[角色] 你是钛合金成形工艺与工效学教学助手。
[知识] 以下是从知识库检索的 3 条依据：...
[任务] 判断学生方案是否存在以下风险：...
[约束] 只输出 JSON，不输出解释。
[格式] {"risks":[{"level":"high|mid|low","item":"...","reason":"..."}]}
```

### 9.3 降级策略

- 模型调用超时 > 5s：返回规则引擎结果
- 模型返回非 JSON：用正则提取，失败则返回默认文案
- 模型不可用：前端显示"AI 建议暂不可用"，实验流程不中断

### 9.4 合规

- 企业真实数据、学生姓名/学号不得进入提示词
- 提示词中的工艺参数先做区间归一化或脱敏
- 所有 AI 调用写 `ai_logs`
- 公共 API 只用于非敏感教学问答

### 10.2 Blender 导出规范

- 格式：glTF 2.0 Binary（.glb）
- 坐标：+Y 向上，单位米
- 原点：物体底面中心
- 变换：应用全部变换（Ctrl+A）
- 材质：Principled BSDF，金属度/粗糙度按实物
- 压缩：Draco
- 命名：小写下划线，无中文、无空格

### 10.3 禁止事项

- 不得使用来源不明的模型/贴图
- 不得使用需付费授权的资产
- 所有资产必须是自制或用 Blender 脚本生成，便于软著登记

## 11. 编码规范与 AI 使用规则

### 11.1 TypeScript

- `strict: true`
- 禁止 `any`（必要时用 `unknown` + 类型守卫）
- 导出函数必须写返回类型
- 仿真函数必须是纯函数，不得有副作用

### 11.2 用 Claude / Codex 的规则

| 场景 | 工具 | 规则 |
|---|---|---|
| 架构、跨模块重构 | Claude | 先出方案再改 |
| 单文件实现、单测 | Codex | 给明确文件路径和验收命令 |
| 3D 场景 | Claude + 本科生 | 先占位，后替换 |
| bpy 脚本 | Codex | 输出可直接运行的 .py |
| 代码审查 | Claude | 提交前跑一遍 |

**所有 AI 生成的代码必须通过 `lint` 和 `test` 才能提交。**

### 11.3 禁止事项

- 不要让 AI 同时改多个模块
- 不要让 AI 自行新增依赖
- 不要让 AI 修改 `packages/shared` 里的契约而不通知对方
- 不要把密钥写进代码或提交到仓库
